# Playbook: Prospect Qualification and Meeting Validation

> **Source:** Prospect Qualification + Meeting Validation Sheet (working execution artefact)  
> **Compiled:** 2026-11-23 | **Status:** Working pre-sales record  
> **Governs with:** [Master Business Architecture](./rcd-master-business-architecture.md) §3.1 and launch gate 1  
> **Next commercial step:** [Services Agreement Baseline](./services-agreement-baseline.md)

Free discovery establishes fit, clarifies the presenting problem and selects the commercial route. Do not provide substantive diagnostic analysis, ranked recommendations or workflow design in this meeting. Record only the minimum pre-sales information. Do not place Customer Confidential or Restricted data on this sheet unless an approved handling arrangement already exists.

The sheet is an internal record. A prefilled personal name in the source template is omitted here. The RCD contact field is the founder or a named delegate.

## 1. Meeting record

| Field | Capture |
| --- | --- |
| Prospect / organisation | Organisation only. Use a client pseudonym once an engagement file is opened |
| Date and attendees | Roles. Do not copy personal contact details into the wiki |
| Sector / location | Enough to test target-market fit |
| RCD contact | Founder or delegate |
| Referral / source | Channel only |
| Decision authority present? | Yes / No / Unknown |
| Confidentiality or data sensitivity raised? | Flag only. Do not paste the sensitive content |

## 2. Basic fit

Score each prompt High, Medium or Low, and keep the note to evidence rather than a recommendation.

| Prompt | What it tests |
| --- | --- |
| Where are skilled people losing time? | A real workflow, not a tool wish |
| What business outcome matters? | The result the buyer will pay for |
| Which teams, processes or customers are affected? | Breadth, without designing the workflow |
| Why address this now? | Urgency |
| What has already been tried? | Prior attempts and constraints |
| Is there a genuine budget and decision path? | Authority and ability to buy |

## 3. Qualification Record for direct-to-PoV

Use this block only when a direct-to-PoV route is in play. That route is an exception. It is available only when the workflow is already bounded and every line below is Sufficient. The record must reach evidence equivalent to the Joint Investment Gate. See architecture Q274–Q279.

| Required evidence | Sufficient? |
| --- | --- |
| Business value and intended outcome | Yes / No |
| Bounded workflow scope and owner | Yes / No |
| Feasibility evidence and known dependencies | Yes / No |
| Data availability, quality and readiness | Yes / No |
| Material operational, privacy, security or delivery risks | Yes / No |
| Human-review and approval requirements | Yes / No |
| Customer decision authority and investment path | Yes / No |

If any line is No, the route is not direct-to-PoV. Prefer a Workflow Friction Map.

## 4. Route decision

Select one route. Introduce a non-WFM service only when the meeting evidence shows that need.

| Route | Use when |
| --- | --- |
| Workflow Friction Map | Normal route. Wider evidence is needed across staff or processes, or the opportunity portfolio is still unclear |
| Direct-to-PoV | Every Qualification Record line is Sufficient for one bounded paid PoV |
| AI Strategy Retainer | A genuine strategic or governance need is established, inside the provisional retainer envelope |
| AI Training and Adoption | A defined capability or adoption need is established. SKU and price stay subject to qualification |
| No engagement / revisit later | Fit, urgency, authority, evidence, economics or capacity is insufficient |

## 5. Qualification gates

Each gate is Pass or Fail. A Fail on economics, capacity or authority stops the recommendation until the founder records a controlled exception.

| Gate | Pass test |
| --- | --- |
| Problem and outcome | A clear business problem and desired outcome |
| Market fit | Appropriate customer and Waikato or other stated target-market fit |
| Capacity | Fits normal capacity, or a justified controlled exception |
| Scope boundary | Can be scoped without free substantive analysis |
| Commercial route | The selected route can meet margin and pricing standards |
| Risk | Appears manageable subject to paid discovery and professional validation |
| Next step | Decision authority and a plausible next step exist |

## 6. Meeting validation

Capture evidence, not a polished narrative:

* Which parts of the proposition were understood immediately, and which needed explanation?
* Which problems and desired outcomes attracted interest?
* What objections or perceived risks were raised?
* What evidence would be needed to proceed?
* What was the perceived value and willingness to pay for the proposed next step?
* Which route fits: WFM, direct-to-PoV, Strategy Retainer, Training and Adoption, another defined service, or no engagement?

## 7. Next action and approval

| Field | Record |
| --- | --- |
| Recommended next action | One action |
| Customer action | What the prospect must do |
| RCD action | What RCD must do |
| Target follow-up date | Date |
| Commercial artefact | WFM proposal, PoV proposal, retainer proposal, training proposal, or none |
| Founder approval | Proceed, Revise or Stop, with date |
| Decision status | Agreed, Provisional, Open or Parked |

Founder approval is required before a proposal is issued. The first live use of this sheet is a validation input to launch gate 1, not a new price-book decision.
